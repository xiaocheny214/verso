# 画像抽取契约

Verso 匹配的是双方能互相补足的能力，不是兴趣相似度。画像回答“这个人能教什么”；本次想学什么由用户的 learning ticket 表达，二者不能混用。

## 判定流程

1. 将知乎授权内容转为最小证据：来源、时间、标题、摘要和原文链接。OAuth token 不进入模型。
2. 分类器为每条证据返回闭集标签、信号、置信度和简短理由。信号只有 `demonstrates_skill`、`interest_only`、`unclear`。
3. 只有高置信度 `demonstrates_skill` 能进入擅长画像。收藏、关注、提问和“想学/不会”等表述不能证明能教。
4. 确定性聚合器负责阈值、去重、排序、时间窗和代表证据；LLM 不直接写画像状态。
5. 未配置模型或模型调用、结构校验失败时使用保守规则。失败不能伪装成模型成功。

## LLM 边界

LLM 用于理解语义，不负责创造事实。输入只包含按时间选取的至多 24 条本人创作；收藏、关注和超出上限的内容走规则分类，避免无上限消耗 token，也避免模型越权。输出必须通过 Pydantic 校验，并完整对应输入证据 ID。

## 评测反例

| 证据 | 期望 |
|---|---|
| 《Python 后端性能优化复盘》及完整实践摘要 | 可判编程能力并返回原文证据 |
| 《零基础怎么学 Python？》 | `unclear`，不得进入擅长 |
| “我不会写代码，想学 Python” | `unclear`，不得进入擅长 |
| 收藏《徒手健身入门》 | `interest_only`，不得进入擅长 |
| 关注健身教练 | `interest_only`，不得进入擅长 |

单元测试只证明契约被执行，不证明真实准确率。是否默认启用 LLM，必须再用匿名金标样本测误报、漏报、延迟和单用户成本。
